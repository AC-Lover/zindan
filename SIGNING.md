# Подпись и безопасные обновления Zindan

Рабочий профиль остаётся связанным с Zindan при обычном обновлении APK, если одновременно
соблюдены три условия:

1. `applicationId` остаётся `net.typeblog.shelter`.
2. Не переименованы компонент владельца профиля и `ShelterDeviceAdminReceiver`.
3. Новый APK подписан тем же ключом, что установленный APK.

Не удаляйте Zindan и не очищайте его данные ради обновления. Перед установкой незнакомой
сборки сначала проверьте совместимость подписи.

## Постоянный сертификат

Локальные сборки 1.5.6 (259) и 1.5.7 (266), созданные на основном компьютере, подписаны
ключом со следующим SHA-256 сертификата:

```text
5306981ed4923615bf9b6ac6ca97d3f5bad2d993afa47cf451aef2baec95e89c
```

Этот сертификат является сертификатом преемственности Zindan. Приватный ключ не должен
попадать в Git, APK, журнал сборки или сообщения. Файлы `*.jks`, `*.keystore` и
`signing.properties` исключены через `.gitignore`.

Основная локальная копия находится в `D:\ZindanSigning\zindan-update.keystore`. Её
случайный пароль хранится в `D:\ZindanSigning\signing-credentials.xml`, зашифрованном
Windows DPAPI для текущего пользователя на текущем компьютере. Скрипт сборки читает его
автоматически. XML нельзя переносить как единственную копию пароля на другой компьютер.

Сделайте зашифрованную резервную копию ключа вне `D:\Zindan5`. Потеря приватного ключа
сделает обновление установленных экземпляров невозможным. Для устройств, на которых APK
имеет другой сертификат, сначала нужна отдельная проверка: ключ выше нельзя подменять
вслепую.

## Локальная сборка

По умолчанию скрипт сначала использует сохранённый ключ
`D:\ZindanSigning\zindan-update.keystore`, затем — существующий локальный ключ
`%USERPROFILE%\.android\debug.keystore`, и проверяет ожидаемый сертификат:

```powershell
cd D:\Zindan5
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\build_local_release.ps1
```

Результат находится в `app\build\outputs\apk\release` и копируется в корень проекта.
Скрипт выводит SHA-256 APK и прекращает работу при несовпадении сертификата.

Для другого пути к сохранённой копии ключа:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\build_local_release.ps1 `
  -KeystorePath "D:\Private\zindan-update.keystore"
```

Также можно создать локальный `signing.properties` по образцу
`signing.properties.example`. Этот файл игнорируется Git.

## Проверка перед установкой

Подключите устройство по ADB, не удаляя установленный Zindan:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\check_apk_update_compatibility.ps1 `
  -ApkPath ".\Zindan-1.5.7-(266)-release.apk"
```

Скрипт извлекает установленный APK только для чтения и сравнивает сертификаты. Устанавливать
APK можно только после сообщения `Compatible`. Сам скрипт ничего на устройство не ставит.

## Публикация на GitHub

Приватный ключ не загружается в GitHub. После коммита изменений и обновления
`version.properties` и `CHANGELOG.md` выполните одну локальную команду:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\publish_local_release.ps1
```

Скрипт требует чистое рабочее дерево, собирает и проверяет подписанный release APK,
создаёт SHA-256, тег и GitHub Release. На GitHub передаются только APK, checksum и текст
релиза. Workflow `Release tag check` дополнительно сверяет тег с `version.properties`,
но ничего не подписывает и не хранит приватный ключ.

## Откат

Откат возможен только на APK с тем же сертификатом. Android обычно запрещает уменьшение
`versionCode`; для тестового отката через ADB применяется `adb install -r -d`, но только
если старая версия умеет читать текущий формат данных. Поэтому последние проверенные APK
и соответствующие исходные теги следует хранить вместе с контрольными суммами.
